- Positive pair definition:
  - visual_robust_ex02 stores several robot embodiment images for the same step/state inside a single dataset sample.
  - In one batch row, image keys such as:
    observation.image
    observation.image.panda_default
    observation.image.ur5e_robotiq85gripper
    observation.image.iiwa_robotiq85gripper
    observation.image.panda_robotiq85gripper
    observation.image.panda_rethinkgripper
    represent the same step/state from different robot embodiments/views.
  - All selected images from the same batch row are treated as positives.
  - Example with BATCH_SIZE=4 and VISUAL_ROBUST_MAX_VIEWS=3:
    row 0 view 0, row 0 view 1, row 0 view 2 are positives of each other.
    row 1 view 0, row 1 view 1, row 1 view 2 are positives of each other.

- Negative pair definition:
  - Images from different batch rows are treated as negatives.
  - Different batch rows correspond to different dataset steps/states.
  - Example with BATCH_SIZE=4 and VISUAL_ROBUST_MAX_VIEWS=3:
    any row 0 view is negative against any row 1, row 2, or row 3 view.

- Label construction:
  - If batch_size = B and num_views = V, the contrastive code creates B * V embeddings.
  - Labels are built as:
    labels = torch.arange(batch_size).repeat_interleave(num_views)
  - Example for B=4 and V=3:
    [0, 0, 0, 1, 1, 1, 2, 2, 2, 3, 3, 3]
  - Same label means positive.
  - Different label means negative.
  - Self-pairs are excluded.

- Contrastive feature:
  - Each selected image is passed through SmolVLA's visual encoder.
  - The encoder output is last_hidden_state with shape approximately:
    [B * V, num_visual_tokens, visual_hidden_dim]
  - The contrastive embedding is:
    z = mean(last_hidden_state, dim=1)
  - Then each z is L2-normalized before similarity computation.

- Contrastive loss equation:
  - Let z_i be the normalized visual feature for image i.
  - Let y_i be its label, where all images from the same step share the same label.
  - Similarity is cosine similarity divided by temperature:
    s(i, j) = (z_i dot z_j) / tau
  - tau is VISUAL_ROBUST_TEMPERATURE.
  - Positive set for anchor i:
    P(i) = { p | y_p = y_i and p != i }
  - The denominator contains all non-self samples:
    A(i) = { a | a != i }
  - Per-anchor loss:
    L_i = - (1 / |P(i)|) * sum_{p in P(i)} log( exp(s(i, p)) / sum_{a in A(i)} exp(s(i, a)) )
  - Final contrastive loss:
    L_contrastive = mean_i L_i
  - Effect:
    Positive pairs appear in the numerator, so the model is trained to increase their similarity.
    Negative pairs appear in the denominator, so high similarity to negatives increases the loss.
    Therefore same-step robot-view features are pulled together and different-step features are pushed apart.

- Final joint training objective:
  - Normal SmolVLA action prediction loss:
    L_vla
  - Auxiliary visual contrastive loss:
    L_contrastive
  - Combined objective:
    L_total = L_vla + lambda * L_contrastive
  - lambda is VISUAL_ROBUST_CONTRASTIVE_WEIGHT.

- Memory-related implementation details:
  - Extra robot-view images are excluded from SmolVLA policy camera metadata so VLA forward does not encode all extra views as action-policy cameras.
  - Extra views are encoded only for the contrastive loss.
  - VISUAL_ROBUST_MAX_VIEWS caps how many views are used per step.
  - VISUAL_ROBUST_ENCODER_CHUNK_SIZE chunks visual encoder calls to reduce peak memory.
  - Validation used BATCH_SIZE=4 and VISUAL_ROBUST_ENCODER_CHUNK_SIZE=8 to confirm correctness without requiring the full memory footprint.

  - The contrastive dataloader used shuffle=True.

- New behavior:
  - Added SameEpisodeBatchSampler in src/lerobot/scripts/lerobot_train_with_visual_robust.py.
  - It reads MultiLeRobotDataset.meta_episodes.
  - For each episode, it uses that episode's dataset_from_index and dataset_to_index frame range.
  - It builds each contrastive batch only from indices inside one episode.
  - Therefore, for visual_robust_ex02:
    - Positive pairs are still different robot-view images from the same sample / same timestep.
    - Negative pairs are now selected image views from different samples / different timesteps in the same episode.
